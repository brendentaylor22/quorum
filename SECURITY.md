# Security policy

Quorum is a self-hosted application handling anonymous votes behind capability
links. Its threat model is written down: [docs/threat-model.md](docs/threat-model.md).

## Reporting a vulnerability

Report privately through GitHub's private vulnerability reporting:
**[Security → Report a vulnerability](https://github.com/brendentaylor22/quorum/security/advisories/new)**.

Please do not open a public issue, and please do not test against an instance
you do not operate.

Useful in a report: affected version or commit, deployment shape (tunnel,
reverse proxy, bare `npm start`), reproduction steps, and what an attacker
gains. A proof of concept against your own local instance is welcome; traffic
against someone else's room is not.

Expect an acknowledgement within 7 days and an assessment within 14. This is a
personal project maintained in spare time — that is the honest commitment, not
an SLA.

## Supported versions

The most recent release only. Quorum ships as a container image published per
commit to `main`; there are no maintenance branches. Fixes land on `main` and
become a new image digest.

## What counts

In scope, and taken seriously:

- Capability token discovery, forgery, or confusion between invite, host, and
  session capabilities.
- Any path from a participant session to another participant's votes, another
  room, or host control.
- Vote forgery, double counting, or results that disagree with stored
  interactions.
- Secret disclosure through logs, responses, the browser bundle, image history,
  or a backup.
- Container escape, unexpected egress from the serving container, or SSRF.
- XSS, CSRF, or clickjacking against the web client.

Out of scope, by design or by documented decision:

- **Invite phrase entropy (~77.5 bits).** A deliberate, bounded trade so the
  link can be read aloud, recorded as T01a in the threat model. A report that
  simply restates the arithmetic is not a finding; a demonstrated practical
  guess within a room's lifetime is.
- **Anyone holding an invite can join.** That is what an invite is. Quorum
  cannot identify real people, and does not try.
- **A stolen participant cookie casts that participant's remaining votes.** An
  accepted residual risk, bounded to one participant in one room.
- Missing hardening on a deployment the operator configured themselves —
  Quorum ships hardened defaults and a documented topology; running the image
  with `--privileged`, a published port on `0.0.0.0`, or a shared token secret
  is an operator choice.
- Volumetric denial of service against an instance you do not run.
- Reports generated by a scanner with no demonstrated impact.

## Operator obligations

Quorum's defaults are safe, but a self-hosted deployment is yours to run:

- Keep `QUORUM_TOKEN_SECRET` (or its file) secret and mode `0400`. Rotating it
  invalidates every live invite, host link, and session — which is also the
  emergency lever if you believe it leaked.
- Deploy by immutable image digest and update when releases land; dependency
  and base-image findings are blocked at release, not retroactively patched in
  an image you already pulled.
- Terminate TLS. Quorum sets `Secure` cookies and refuses to relax them when
  `NODE_ENV=production`; serving it over plain HTTP in production will not work
  and should not be made to.
- Never publish a database backup. It contains bulk TMDB metadata as well as
  room data.

See [docs/self-hosting.md](docs/self-hosting.md) for the install and
[docs/operations.md](docs/operations.md) for backups, upgrades, and rollback.
How dependency and image findings are handled:
[docs/dependency-policy.md](docs/dependency-policy.md).
